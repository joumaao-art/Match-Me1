# Project Summary
MatchMe is an enterprise recruiting platform that connects job seekers and hiring teams through swipe-based matching, career intelligence, and AI-assisted recruiting workflows. It supports messaging, interviews, pipelines, offers, hiring, analytics, monetization, and governed employer operations.

The Job Seeker signup flow now uses centralized, idempotent initialization. Authentication resolves the session, creates or reuses the Job Seeker identity and onboarding state, clears loading states on every outcome, and routes new users to the Welcome screen before progressive onboarding. Existing users resume incomplete onboarding or enter the normal seeker experience. Company authentication and MatchMe branding remain unchanged.

# Project Module Description
- **Job Seeker Authentication:** Supports email, Apple, Google, and phone OTP integration paths. Provider availability depends on Supabase configuration.
- **Signup Flow Orchestration:** Centralizes authentication completion, session resolution, identity initialization, onboarding initialization, routing, failure recovery, and retry behavior.
- **Idempotent Profile Initialization:** Creates or reuses Job Seeker records safely using the authenticated user ID, preventing duplicate or conflict errors during retries and callbacks.
- **Loading and Failure Recovery:** Ensures asynchronous signup and initialization operations terminate in success or recoverable error states instead of leaving permanent loaders.
- **OAuth and OTP Callback Handling:** Reuses the same post-authentication bootstrap flow for email, phone, Apple, and Google paths.
- **Job Seeker Onboarding Engine:** Provides resumable steps, validation, persistence, skip rules, completion tracking, analytics, and progressive initialization.
- **Profile Creation and Setup:** Supports resume-assisted and manual profile creation, preferences, demographic information, locations, notifications, profile review, plans, and Discover preparation.
- **Routing and Guards:** Distinguishes unauthenticated users, incomplete and complete Job Seekers, Company users, and other roles. New or incomplete Job Seekers are allowed into onboarding.
- **Localization:** Supports English, Arabic, and RTL layouts.
- **Diagnostics:** Includes development probes for authentication and signup-flow investigation.

# File Description Inventory
- `app/frontend/src/App.tsx`: Initializes authentication, processes OAuth and phone callbacks, and routes authenticated users through the shared signup bootstrap.
- `app/frontend/src/pages/Auth.tsx`: Provides email, Apple, Google, phone OTP, login, retry, and role-specific authentication flows while preserving Company behavior.
- `app/frontend/src/lib/signup-flow.ts`: Coordinates session resolution, Job Seeker identity creation, onboarding initialization, loading cleanup, error recovery, and destination routing.
- `app/frontend/src/services/auth.service.ts`: Implements email authentication, OAuth, phone OTP, session handling, and authentication-related error propagation.
- `app/frontend/src/services/profile.service.ts`: Reads and writes Job Seeker profile and onboarding records with user-ID-based idempotency.
- `app/frontend/src/pages/JobSeeker.tsx`: Routes incomplete users to resumable onboarding and completed users to the seeker dashboard.
- `app/frontend/src/pages/JobSeekerOnboarding.tsx`: Renders the progressive onboarding workflow beginning with Welcome.
- `app/frontend/src/lib/onboarding-engine.ts`: Defines onboarding steps, state transitions, validation, persistence, skip behavior, completion, and analytics integration.
- `app/frontend/src/components/onboarding/OnboardingKit.tsx`: Contains reusable onboarding layouts, actions, progress UI, signup controls, OTP input, and selection components.
- `app/frontend/packages/shared/src/constants/index.ts`: Stores shared routes, onboarding constants, and pending-role keys.
- `app/frontend/packages/shared/src/i18n/en.ts`: English authentication and onboarding translations.
- `app/frontend/packages/shared/src/i18n/ar.ts`: Arabic authentication and onboarding translations with RTL support.
- `app/frontend/scripts/probe-auth-deadlock.mjs`: Tests whether authentication callbacks produce unresolved promise behavior.
- `app/frontend/scripts/probe-signup-flow.mjs`: Verifies signup persistence, conflict behavior, and initialization sequencing.
- `app/frontend/seo/content/*.md`: SEO article content.
- `app/frontend/docs/enterprise/*.md`: Enterprise API, governance, matching, workflow, data, and monetization specifications.

# Technology Stack
- **Frontend:** Vite, React, TypeScript, Tailwind CSS
- **Mobile:** React Native, Expo
- **Backend:** Supabase, Node.js, PostgreSQL
- **State Management:** React Context API, Zustand
- **Authentication:** Supabase Auth with email, OAuth, and phone OTP
- **Internationalization:** i18next with English and Arabic/RTL support
- **Workspace:** pnpm monorepo
- **Validation:** TypeScript, ESLint, production Vite builds, and diagnostic signup probes

# Usage
1. Install frontend dependencies:
   ```bash
   cd app/frontend
   pnpm install
   ```
2. Start the frontend:
   ```bash
   pnpm run start
   ```
3. Build the production frontend:
   ```bash
   pnpm run build
   ```
4. Run the mobile application:
   ```bash
   cd app/mobile
   expo start
   ```
5. Run signup diagnostics when investigating authentication or persistence issues:
   ```bash
   node scripts/probe-auth-deadlock.mjs
   node scripts/probe-signup-flow.mjs
   ```
6. Configure Supabase OAuth providers, phone OTP, redirect settings, and session persistence before validating those production authentication paths. The current environment must explicitly enable Apple, Google, or phone authentication for end-to-end provider testing.
