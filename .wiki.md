# Project Summary
MatchMe is an enterprise recruiting platform connecting job seekers and hiring teams through swipe-based matching, career intelligence, and AI-assisted recruiting workflows. It supports authentication, onboarding, messaging, interviews, hiring pipelines, offers, analytics, monetization, and governed employer operations.

Job Seeker signup now completes in the real application without an infinite full-screen loader. The primary runtime issue was an unbounded `GuestRoute` destination-resolution loader that replaced the signup UI immediately after authentication succeeded. Pending destination resolution now leaves the route content visible and redirects only after a destination is available. Runtime loader identities, browser-based end-to-end checks, regression coverage, and English-only engineering documentation were added.

# Project Module Description
- **Job Seeker Authentication:** Supports email, Apple, Google, and phone OTP integration paths, subject to Supabase provider configuration.
- **Authentication Boot:** Resolves sessions with explicit loading states, bounded operations, error handling, diagnostics, and deterministic release.
- **Public Authentication Routes:** Signup and login render independently of private profile, onboarding, subscription, and dashboard initialization.
- **Guest Route Resolution:** Keeps public route content visible while destination resolution is pending and redirects only after a destination is resolved.
- **Signup Flow Orchestration:** Coordinates authentication, session resolution, identity initialization, onboarding initialization, routing, failure recovery, and retries.
- **Idempotent Profile Initialization:** Creates or reuses Job Seeker records using the authenticated user ID.
- **Onboarding Hydration:** Loads server or local onboarding state with bounded requests and settled fallback behavior.
- **Job Seeker Route Guards:** Protects dashboard and onboarding routes while releasing on success, fallback, timeout, or authentication failure.
- **Loader Diagnostics:** Assigns development-only identities to full-screen loaders and captures runtime route, console, request, and loader-state evidence.
- **Runtime Verification:** Uses real-browser signup, refresh, authentication, routing, mobile, and Company regression checks.
- **Localization:** Supports English and Arabic with RTL layouts. Intentional language metadata remains unchanged.
- **Documentation and Language Audit:** Maintains English technical documentation and checks engineering content for unintended Chinese text.

# Technology Stack
- **Frontend:** Vite, React, TypeScript, Tailwind CSS
- **Mobile:** React Native, Expo
- **Backend:** Supabase, Node.js, PostgreSQL
- **State Management:** React Context API, Zustand
- **Authentication:** Supabase Auth with email, OAuth, and phone OTP
- **Internationalization:** i18next with English and Arabic/RTL support
- **Workspace:** pnpm monorepo
- **Validation:** TypeScript, ESLint, production builds, real-browser runtime harnesses, regression matrices, and diagnostic probes
- **Resilience:** Explicit authentication states, bounded async operations, deterministic loading release, and route-level fallback behavior

# Usage
1. Install frontend dependencies:
   ```bash
   cd app/frontend
   pnpm install
   ```

2. Start the frontend:
   ```bash
   pnpm run start
   ```

3. Build the production frontend:
   ```bash
   pnpm run build
   ```

4. Run the mobile application:
   ```bash
   cd app/mobile
   expo start
   ```

5. Run authentication and signup diagnostics:
   ```bash
   cd app/frontend
   node scripts/probe-auth-deadlock.mjs
   node scripts/probe-signup-flow.mjs
   node scripts/repro-signup-spinner-hang.mjs
   ```

6. Run real-browser runtime validation:
   ```bash
   cd app/frontend
   node scripts/runtime-signup-e2e.mjs
   node scripts/runtime-signup-repro.mjs
   node scripts/runtime-auth-matrix.mjs
   ```

7. Configure Supabase providers, phone OTP, redirect settings, session persistence, and required environment variables before testing provider-specific authentication. Configuration failures should surface as explicit errors rather than indefinite loading.
