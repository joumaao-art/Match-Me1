# Project Summary
MatchMe is an enterprise Talent Platform that connects job seekers and hiring teams using swipe-style compatibility and AI-powered matching, then drives end-to-end recruiting via workflows, messaging/notifications, analytics, and measurable hiring outcomes. The platform standardizes implementation through reusable Platform Engines and governance-ready reference blueprints to keep web/mobile experiences secure, observable, testable, and compliant.

# Project Module Description
## Platform Reference Implementation (Prompt 4C)
Provides the canonical end-to-end enterprise blueprint describing how the platform stack layers compose (experience engines, workflow/business/AI/security engines, and infrastructure/operations), including core user journeys, engine dependency directionality, composition guidance, registries/governance assets, operational dashboards, and disaster recovery/deployment conventions. It also defines the strategic rule that new modules/engines/capabilities must reuse approved components/workflows, publish events, update registries, and pass validation/governance.

## SEO Content Additions
Maintains a set of frontend SEO article pages for MatchMe’s AI swipe recruitment overview, AI resume intelligence skills matching, bilingual recruitment for the Middle East, enterprise recruitment security with RBAC, and recruiting analytics/dashboards for hiring outcomes.

## Enterprise Data Platform Specification (Prompt 5 — Part 1)
Defines the official Enterprise Data Platform architecture responsible for storage, organization, governance, security, quality, lifecycle, and accessibility of all platform data across multiple enterprise products. Establishes data philosophy/principles, multi-layer architecture boundaries, 12 independent enterprise data domains, canonical data modeling (single-instance business concepts), mandatory entity standards/identifiers, multi-tenant isolation model, lifecycle/versioning expectations, search integration requirements, AI readiness metadata, immutable audit requirements, governance/security/classification/retention expectations, platform registries, and required validation gates. Concludes with the strategic recommendation to introduce a Canonical Data Model Engine as the authoritative guardian of all enterprise entities.

# Technology Stack
- Frontend: Vite, React, TypeScript, Tailwind CSS
- Mobile: React Native, Expo
- Backend: Supabase, Node.js, PostgreSQL
- State Management: React Context API, Zustand
- Internationalization: i18next

# Usage
1. Install dependencies (web):
   - Run `pnpm install` in `app/frontend`
2. Build the web app:
   - Run `pnpm run build` in `app/frontend`
3. Run:
   - Web: Run `pnpm run start` in `app/frontend`
   - Mobile: Run `expo start` in `app/mobile`
