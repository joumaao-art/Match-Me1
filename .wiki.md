# Project Summary

MatchMe is an enterprise recruiting platform connecting job seekers and hiring teams through swipe-based matching, career intelligence, and AI-assisted recruiting workflows. It supports authentication, onboarding, messaging, interviews, hiring pipelines, offers, analytics, monetization, governed employer operations, and English/Arabic localization.

The current implementation repairs authenticated Job Seeker navigation. A shared idempotent initialization authority now recovers partially initialized accounts, normalizes onboarding state, prevents onboarding/dashboard redirect loops, and ensures the “Get started” and “Dashboard” paths settle without indefinite full-screen loading. Existing signup classification, Company functionality, localization, and engineering-language governance remain preserved.

# Project Module Description

- **Job Seeker Authentication:** Supports email, Apple, Google, and phone OTP integration paths through Supabase configuration.
- **Signup Outcome Classification:** Distinguishes `authenticated`, `verification_required`, and `error` outcomes.
- **Authentication Boot:** Resolves sessions with bounded operations, diagnostics, error handling, and deterministic loading release.
- **Public and Private Routing:** Keeps public authentication independent from private Job Seeker and Company initialization.
- **Job Seeker Bootstrap:** Uses an idempotent initialization authority to ensure required identity, profile, role, and onboarding records without overwriting completed data or creating fabricated content.
- **Partial Account Recovery:** Repairs missing application records for authenticated Job Seekers created by earlier broken signup flows.
- **Destination Resolution:** Produces finite onboarding or dashboard decisions and avoids competing redirect decisions.
- **Onboarding Hydration:** Normalizes persisted and local state, treating missing onboarding records as valid not-started state rather than permanent loading.
- **Job Seeker Dashboard:** Renders or redirects based on the authoritative bootstrap result and avoids blocking the dashboard shell on secondary data.
- **Get Started Flow:** Opens the appropriate first onboarding/profile-building page without an infinite loader.
- **Redirect Loop Prevention:** Prevents repeated `/seeker` and `/seeker/onboarding` navigation caused by inconsistent local and server completion state.
- **Localization:** Supports English and Arabic with RTL layouts.
- **Engineering Language Governance:** Requires English for engineering-controlled communication and documentation while preserving product localization.
- **Runtime Verification:** Covers partial and completed accounts, signup, authentication, navigation, refresh, back/forward behavior, mobile layout, and language validation.

# Technology Stack

- **Frontend:** Vite, React, TypeScript, Tailwind CSS
- **Mobile:** React Native, Expo
- **Backend:** Supabase, Node.js, PostgreSQL
- **State Management:** React Context API, Zustand
- **Authentication:** Supabase Auth with email, OAuth, and phone OTP
- **Internationalization:** i18next with English and Arabic/RTL support
- **Workspace:** pnpm monorepo
- **Validation:** TypeScript, ESLint, production builds, browser harnesses, regression matrices, and language scanning
- **Resilience:** Idempotent bootstrap, normalized state, finite destination resolution, recoverable missing records, and deterministic loading release

# Usage

1. Install frontend dependencies:

   ```bash
   cd app/frontend
   pnpm install
   ```

2. Start the frontend:

   ```bash
   pnpm run start
   ```

3. Build the production frontend:

   ```bash
   pnpm run build
   ```

4. Run the mobile application:

   ```bash
   cd app/mobile
   expo start
   ```

5. Run language validation:

   ```bash
   cd app/frontend
   pnpm run check:language
   ```

6. Run Job Seeker routing diagnostics:

   ```bash
   cd app/frontend
   node scripts/repro-seeker-redirect-loop.mjs
   node scripts/runtime-seeker-navigation.mjs
   node scripts/runtime-seeker-account-states.mjs
   ```

7. Run authentication and signup diagnostics:

   ```bash
   cd app/frontend
   node scripts/probe-auth-deadlock.mjs
   node scripts/probe-signup-flow.mjs
   node scripts/repro-signup-spinner-hang.mjs
   node scripts/probe-email-signup-matrix.mjs
   node scripts/probe-email-signup-transition.mjs
   node scripts/probe-signup-classifier.mjs
   node scripts/probe-signup-outcomes.mjs
   ```

8. Run real-browser signup and authentication validation:

   ```bash
   cd app/frontend
   node scripts/runtime-signup-e2e.mjs
   node scripts/runtime-signup-repro.mjs
   node scripts/runtime-auth-matrix.mjs
   ```

9. Configure Supabase providers, email confirmation, redirect settings, session persistence, database policies, and required environment variables before provider-specific testing. Missing profile or onboarding records must be recoverable application states.
