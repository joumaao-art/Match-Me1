# Project Summary

MatchMe is a recruiting marketplace for job seekers to discover and apply for vacancies and for employers to publish roles and review applicants. It provides Job Seeker, Company, and Admin experiences, supports English and Arabic, and persists marketplace activity through Supabase.

Job Seeker features include vacancy discovery, Swipe decisions, applications, saved jobs, profile guidance, and credits. VIA Premium offers monthly and yearly plans: Monthly remains selectable at $10/month, while Yearly is selected by default at $100/year and is the only plan marked “Most Popular.” Company workflows cover profiles, vacancy publication, and applicant review.

TypeScript, 126 regression checks, lint, and the production build passed. Authenticated mobile interaction and sandbox checkout remain unverified. Payment release is still blocked pending complete Stripe webhook configuration and a verified sandbox transaction. Native purchases remain disabled pending approved store billing.

# Project Module Description

- **Authentication and routing:** Signup, login, verification, role-based routes, and shared-job authentication recovery.
- **Mobile onboarding:** Eleven semantic onboarding steps with account-isolated draft recovery, validation, and derived birthday age display.
- **Job Seeker experience:** Swipe, Dashboard, and Profile navigation, with persisted applications, matches, saves, credits, and profile completion.
- **Vacancy discovery and decisions:** Vacancy discovery and ranking fallback, eligibility guidance, and persisted actions with ownership, duplicate, credit, and expiry safeguards.
- **Company marketplace:** Persisted Company profiles, private logo storage, vacancy drafts and publication, dashboard counts, and applicant review.
- **Applications and matches:** Company review decisions update application statuses and seeker matches.
- **VIA Premium and credits:** Credits popup, Monthly and Yearly plan selection, subscription management, and server-derived Premium eligibility. Yearly is the fresh-page default; existing pending checkouts retain their original plan.
- **Payments and entitlements:** Stripe checkout and verification use server-side catalog validation; subscription lifecycle updates require verified webhook signatures. Premium is not activated from unverified payment state.
- **Shared job links:** Stable vacancy IDs support web landing pages and authentication recovery. Android App Links require deployment configuration.
- **Profiles, messaging, and localization:** Shared profile and history records, preference management, existing messaging, English/Arabic translations, and Company/Admin portals. Live chat and unread-count consistency are not established.

# Technology Stack

- **Frontend:** React, TypeScript, Vite, Tailwind CSS
- **Native app:** Expo and React Native, with a shared-screen WebView container
- **Backend and data:** Supabase, Node.js, PostgreSQL
- **Authentication:** Supabase Auth
- **State management:** React Context API, Zustand
- **Payments:** Stripe checkout and webhook integration with server-side verification
- **Internationalization:** i18next, English and Arabic/RTL
- **Workspace:** pnpm monorepo
- **Validation:** TypeScript, ESLint, production builds, contract checks, and rollback-only database tests

# Usage

1. Install frontend dependencies:

   ```bash
   cd app/frontend
   pnpm install
   ```

2. Start the frontend:

   ```bash
   pnpm run start
   ```

3. Build the production frontend:

   ```bash
   pnpm run build
   ```

4. Validate translations:

   ```bash
   pnpm run check:language
   ```

5. Run marketplace, Premium, Swipe, navigation, and onboarding contracts:

   ```bash
   node scripts/live-marketplace-contract.mjs
   node scripts/via-premium-contract.mjs
   node scripts/mobile-swipe-contract.mjs
   node scripts/seeker-navigation-contract.mjs
   node scripts/mobile-onboarding-contract.mjs
   ```

6. Run available runtime diagnostics:

   ```bash
   node scripts/runtime-onboarding-isolation.mjs
   node scripts/runtime-seeker-navigation.mjs
   node scripts/runtime-seeker-account-states.mjs
   node scripts/runtime-auth-matrix.mjs
   node scripts/runtime-signup-e2e.mjs
   ```

7. Configure Supabase, apply the required migrations, and deploy payment functions with the required Stripe secrets. Complete webhook configuration and verify a sandbox transaction before enabling paid access. Android App Links require deployment-specific domain association, package and signing fingerprints, and device/build access. Native purchases remain disabled pending approved store billing.
