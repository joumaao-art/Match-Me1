# Project Summary

MatchMe is an enterprise recruiting platform connecting job seekers and hiring teams through swipe-based matching, career intelligence, and AI-assisted recruiting workflows. It supports authentication, onboarding, messaging, interviews, hiring pipelines, offers, analytics, monetization, governed employer operations, and English/Arabic product localization.

The latest maintenance work establishes an English-only engineering communication and documentation policy, adds automated detection for accidental Chinese engineering text, and verifies that signup, authentication, onboarding, localization, and routing behavior remain unchanged.

# Project Module Description

- **Job Seeker Authentication:** Supports email, Apple, Google, and phone OTP integration paths through Supabase configuration.
- **Email Signup Outcomes:** Classifies signup as `authenticated`, `verification_required`, or `error` based on the authentication response.
- **Email Verification Flow:** Preserves pending email state and presents a recoverable verification experience when no session is returned.
- **Authentication Boot:** Resolves sessions with bounded operations, diagnostics, error handling, and deterministic loading release.
- **Public Authentication Routes:** Keeps signup and login independent from private profile, onboarding, subscription, and dashboard initialization.
- **Guest Route Resolution:** Displays public content while destination resolution is pending and redirects only after resolution.
- **Signup Flow Orchestration:** Coordinates authentication, identity initialization, onboarding, routing, recovery, and retries.
- **Profile Initialization:** Creates or reuses Job Seeker records by authenticated user ID and avoids unauthenticated writes.
- **Onboarding Hydration:** Loads server or local onboarding state with bounded requests and settled fallback behavior.
- **Job Seeker Route Guards:** Protects dashboard and onboarding routes with success, fallback, timeout, and authentication-failure release paths.
- **Loader Diagnostics:** Provides development-only loader identities and runtime evidence.
- **Localization:** Supports English and Arabic with RTL layouts. Approved native language metadata remains intact.
- **Engineering Language Governance:** Requires English for engineering documentation, comments, logs, test descriptions, architecture documents, and agent communication while preserving English and Arabic product localization.
- **Language Validation:** Scans engineering-controlled files for unexpected Han characters without flagging Arabic or approved locale metadata.
- **Runtime Verification:** Covers signup, verification, refresh, login, Company authentication, mobile behavior, and onboarding regression scenarios.

# Technology Stack

- **Frontend:** Vite, React, TypeScript, Tailwind CSS
- **Mobile:** React Native, Expo
- **Backend:** Supabase, Node.js, PostgreSQL
- **State Management:** React Context API, Zustand
- **Authentication:** Supabase Auth with email, OAuth, and phone OTP
- **Internationalization:** i18next with English and Arabic/RTL support
- **Workspace:** pnpm monorepo
- **Validation:** TypeScript, ESLint, production builds, runtime harnesses, regression matrices, diagnostic scripts, and engineering-language scanning
- **Resilience:** Explicit authentication outcomes, bounded async operations, deterministic loading release, persisted verification state, and route-level fallback behavior

# Usage

1. Install frontend dependencies:

   ```bash
   cd app/frontend
   pnpm install
   ```

2. Start the frontend:

   ```bash
   pnpm run start
   ```

3. Build the production frontend:

   ```bash
   pnpm run build
   ```

4. Run the mobile application:

   ```bash
   cd app/mobile
   expo start
   ```

5. Run the language validation:

   ```bash
   cd app/frontend
   pnpm run check:language
   ```

6. Run authentication and signup diagnostics:

   ```bash
   cd app/frontend
   node scripts/probe-auth-deadlock.mjs
   node scripts/probe-signup-flow.mjs
   node scripts/repro-signup-spinner-hang.mjs
   node scripts/probe-email-signup-matrix.mjs
   node scripts/probe-email-signup-transition.mjs
   node scripts/probe-signup-classifier.mjs
   node scripts/probe-signup-outcomes.mjs
   ```

7. Run real-browser runtime validation:

   ```bash
   cd app/frontend
   node scripts/runtime-signup-e2e.mjs
   node scripts/runtime-signup-repro.mjs
   node scripts/runtime-auth-matrix.mjs
   ```

8. Configure Supabase providers, email confirmation, redirect settings, session persistence, and required environment variables before provider-specific authentication testing. A signup response containing a user but no session must render a verification-required state rather than wait indefinitely.
