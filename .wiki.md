# Project Summary
MatchMe is an enterprise recruiting platform that connects job seekers and hiring teams through swipe-based matching, career intelligence, and AI-assisted recruiting workflows. It supports messaging, interviews, pipelines, offers, hiring, analytics, monetization, and governed employer operations.

Job Seeker authentication and onboarding now release all critical loading gates deterministically. Auth initialization, onboarding hydration, and the Job Seeker dashboard guard use bounded operations, fallback paths, and development diagnostics so pending or failed session/profile requests cannot leave users on an infinite spinner. Logged-out users can reach authentication screens immediately, while authenticated Job Seekers continue through Welcome and resumable onboarding.

# Project Module Description
- **Job Seeker Authentication:** Supports email, Apple, Google, and phone OTP integration paths. Provider availability depends on Supabase configuration.
- **Authentication Boot:** Resolves sessions with error handling, timeouts, final state release, and development boot tracing.
- **Public Route Access:** Login and signup screens do not wait for profile, onboarding, subscription, or other private application data.
- **Signup Flow Orchestration:** Centralizes authentication completion, session resolution, Job Seeker identity initialization, onboarding initialization, routing, failure recovery, and retry behavior.
- **Idempotent Profile Initialization:** Creates or reuses Job Seeker records safely using the authenticated user ID.
- **Onboarding Hydration:** Loads server or local onboarding state with bounded requests and guarantees hydration completion on success, failure, timeout, or malformed data.
- **Job Seeker Route Guards:** Releases dashboard and onboarding guards after successful checks, fallback recovery, or timeout, and redirects unauthenticated users without indefinite loading.
- **Loading Diagnostics:** Includes boot traces, bounded initialization gates, a watchdog-style timeout strategy, and a reproducible hanging-promise diagnostic.
- **Localization:** Supports English, Arabic, and RTL layouts.
- **Diagnostics and Documentation:** Records the signup spinner root cause, execution trace, reproduction evidence, and validation results.

# File Description Inventory
- `app/frontend/src/App.tsx`: Controls the top-level auth loading gate, applies bounded session initialization, releases loading on every outcome, and emits development boot traces.
- `app/frontend/src/lib/onboarding-engine.ts`: Hydrates onboarding state through bounded server/local reads and always transitions to a settled hydrated state.
- `app/frontend/src/pages/JobSeeker.tsx`: Applies a bounded onboarding check and releases the dashboard guard on success, fallback, or timeout.
- `app/frontend/src/pages/JobSeekerOnboarding.tsx`: Renders onboarding after hydration settles and prevents profile reads from holding the screen indefinitely.
- `app/frontend/src/lib/signup-flow.ts`: Coordinates session, identity, onboarding, and destination resolution with shared timeout handling.
- `app/frontend/src/pages/Auth.tsx`: Provides email, Apple, Google, phone OTP, login, retry, and role-specific authentication flows without private profile dependencies.
- `app/frontend/src/services/auth.service.ts`: Implements email authentication, OAuth, phone OTP, session handling, and authentication-related error propagation.
- `app/frontend/src/services/profile.service.ts`: Reads and writes Job Seeker profile and onboarding records with user-ID-based idempotency.
- `app/frontend/src/scripts/repro-signup-spinner-hang.mjs`: Demonstrates that the former unbounded gate remains hung while the corrected gate releases on pending and rejected operations.
- `app/frontend/docs/enterprise/SignupSpinnerRootCause.md`: Documents the three spinner owners, blocking states, root cause, previous-fix limitation, surgical corrections, verification trace, and validation results.
- `app/frontend/scripts/probe-auth-deadlock.mjs`: Tests whether authentication callbacks produce unresolved promise behavior.
- `app/frontend/scripts/probe-signup-flow.mjs`: Verifies signup persistence, conflict behavior, and initialization sequencing.
- `app/frontend/packages/shared/src/constants/index.ts`: Stores shared routes, onboarding constants, and pending-role keys.
- `app/frontend/packages/shared/src/i18n/en.ts`: English authentication and onboarding translations.
- `app/frontend/packages/shared/src/i18n/ar.ts`: Arabic authentication and onboarding translations with RTL support.
- `app/frontend/seo/content/*.md`: SEO article content.
- `app/frontend/docs/enterprise/*.md`: Enterprise API, governance, matching, workflow, data, monetization, and debugging specifications.

# Technology Stack
- **Frontend:** Vite, React, TypeScript, Tailwind CSS
- **Mobile:** React Native, Expo
- **Backend:** Supabase, Node.js, PostgreSQL
- **State Management:** React Context API, Zustand
- **Authentication:** Supabase Auth with email, OAuth, and phone OTP
- **Internationalization:** i18next with English and Arabic/RTL support
- **Workspace:** pnpm monorepo
- **Validation:** TypeScript, ESLint, production Vite builds, diagnostic probes, and spinner reproduction tests
- **Resilience:** Bounded async gates, timeout fallback handling, deterministic loading release, and development boot tracing

# Usage
1. Install frontend dependencies:
   ```bash
   cd app/frontend
   pnpm install
   ```

2. Start the frontend:
   ```bash
   pnpm run start
   ```

3. Build the production frontend:
   ```bash
   pnpm run build
   ```

4. Run the mobile application:
   ```bash
   cd app/mobile
   expo start
   ```

5. Run authentication and signup diagnostics:
   ```bash
   cd app/frontend
   node scripts/probe-auth-deadlock.mjs
   node scripts/probe-signup-flow.mjs
   node scripts/repro-signup-spinner-hang.mjs
   ```

6. Configure Supabase OAuth providers, phone OTP, redirect settings, session persistence, and required environment variables before validating provider flows. Missing or invalid configuration should be handled as a controlled initialization error rather than an indefinite loading state.
