# Project Summary
MatchMe is an enterprise talent platform that matches job seekers and hiring teams using swipe-style compatibility and AI matching, then drives end-to-end recruiting through governed workflows, messaging/notifications, analytics, and measurable hiring outcomes. The project standardizes delivery via reusable Platform Engines and governance-ready reference documentation to keep experiences secure, observable, testable, and compliant.

# Project Module Description
## Platform Reference Implementation (Prompt 4C)
Canonical end-to-end blueprint for composing platform layers (experience engines, workflow/business/AI/security engines, and infrastructure/operations), including core journeys, engine dependency directionality, composition guidance, registries/governance assets, operational dashboards, and deployment/disaster recovery conventions. Enforces rule: new modules/engines/capabilities must reuse approved components/workflows, publish events, update registries, and pass validation/governance.

## SEO Content Additions
Frontend SEO article pages covering MatchMe AI recruiting overview, AI resume intelligence skill matching, bilingual recruitment for the Middle East, enterprise recruiting security with RBAC, and recruiting analytics/dashboards for hiring outcomes.

## Enterprise Data Platform Specification (Prompt 5)
Enterprise data architecture defining storage, organization, governance, security, quality, lifecycle, and accessibility across enterprise products. Includes data philosophy/principles, multi-layer boundaries, canonical data modeling (single-instance business concepts), entity standards/identifiers, multi-tenant isolation, lifecycle/versioning, search integration, AI readiness metadata, immutable audit requirements, governance/security/classification/retention expectations, registries, and validation gates. Recommends a Canonical Data Model Engine as the authoritative guardian of enterprise entities.

## Canonical Entity Model (Prompt 5 Part 2)
Defines the Canonical Entity Model (CEM): the authoritative, platform-wide definitions for every business entity. Establishes canonical philosophy (one business concept → one entity; no duplication/redefinition), entity categories and domain entities, explicit versioned/documented relationships with validation rules, naming standards, entity registry requirements, metadata standards, and deliverables (entity catalog, ownership/relationship matrices, dictionary, validation reports, registry updates, roadmap). Specifies that no module may create or redefine entities outside the model, and that all schemas/APIs/workflows/AI/search/analytics must reference canonical entities. Introduces the Enterprise Metadata Engine as the single source of truth for entity metadata and evolution.

# Technology Stack
- Frontend: Vite, React, TypeScript, Tailwind CSS
- Mobile: React Native, Expo
- Backend: Supabase, Node.js, PostgreSQL
- State Management: React Context API, Zustand
- Internationalization: i18next

# Usage
1. Install dependencies (web):
   - Run `pnpm install` in `app/frontend`
2. Build the web app:
   - Run `pnpm run build` in `app/frontend`
3. Run:
   - Web: Run `pnpm run start` in `app/frontend`
   - Mobile: Run `expo start` in `app/mobile`
