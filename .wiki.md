# Project Summary

MatchMe is an enterprise recruiting platform connecting job seekers and employers through job discovery, applications, profiles, messaging, and recruiting workflows. It supports Job Seeker, Company, and Admin experiences, with English and Arabic localization.

The Job Seeker experience includes mobile onboarding and a Swipe page for reviewing vacancies, managing job decisions, and opening job details. Recent work adds a mobile-focused Swipe experience, expands the canonical vacancy data and Company posting workflow, and supports stable web links for individual jobs. Desktop Swipe rendering and the existing three-tab mobile navigation remain preserved.

The implementation passed frontend checks and available database integration tests. Signed-in mobile visual acceptance and Android device behavior remain unverified. Android App Links require deployment-specific configuration and credentials.

# Project Module Description

- **Authentication and routing:** Signup, login, verification, role-based routes, and job-link authentication recovery.
- **Mobile onboarding:** Eleven semantic onboarding steps with account-isolated draft recovery, validation, and derived birthday age display.
- **Job Seeker navigation:** Mobile Swipe, Dashboard, and Profile tabs, synchronized with seeker routes. Dashboard shortcuts include Messages, Applications, and Matches.
- **Mobile Swipe:** Job cards show available vacancy details and support Undo, Share, Save, Pass, Apply, and expandable details. Profile-completion guidance helps users address eligibility requirements.
- **Vacancies and Company posting:** Company forms and canonical vacancy services support salary/package, location, employment type and style, description, and qualifications. New metadata is nullable; existing vacancies are not filled with invented information.
- **Job decisions and credits:** Persisted job actions retain ownership checks, duplicate prevention, credit accounting, and safeguards for expired vacancies.
- **Shared job links:** Stable vacancy IDs power web job landing pages and authentication recovery. Android incoming-link handling is prepared but requires deployment configuration.
- **Profiles and preferences:** Profile and history records are shared with account editors. Preferences include roles, keywords, working styles, work types, and seniority.
- **Messaging, localization, and portals:** Existing messaging, English/Arabic translations, Company portal, and Admin portal remain available. Live chat and unread-count consistency are not established.

# Technology Stack

- **Frontend:** React, TypeScript, Vite, Tailwind CSS
- **Native app:** Expo and React Native, with a shared-screen WebView container
- **Backend and data:** Supabase, Node.js, PostgreSQL
- **Authentication:** Supabase Auth
- **State management:** React Context API, Zustand
- **Payments:** Stripe integration with server-side verification
- **Internationalization:** i18next, English and Arabic/RTL
- **Workspace:** pnpm monorepo
- **Validation:** TypeScript, ESLint, production builds, contract checks, and database integration tests

# Usage

1. Install frontend dependencies:

   ```bash
   cd app/frontend
   pnpm install
   ```

2. Start the frontend:

   ```bash
   pnpm run start
   ```

3. Build the production frontend:

   ```bash
   pnpm run build
   ```

4. Validate translations:

   ```bash
   pnpm run check:language
   ```

5. Run the Swipe, navigation, and onboarding contracts:

   ```bash
   node scripts/mobile-swipe-contract.mjs
   node scripts/seeker-navigation-contract.mjs
   node scripts/mobile-onboarding-contract.mjs
   ```

6. Run available runtime diagnostics:

   ```bash
   node scripts/runtime-onboarding-isolation.mjs
   node scripts/runtime-seeker-navigation.mjs
   node scripts/runtime-seeker-account-states.mjs
   node scripts/runtime-auth-matrix.mjs
   node scripts/runtime-signup-e2e.mjs
   ```

7. Configure Supabase, apply required migrations, and provide Stripe and location-provider credentials as needed. Android App Links additionally require the deployment origin, package and signing fingerprints, verified domain association, and device/build access.

The reported frontend verification passed 106 contract checks, TypeScript, ESLint, and the production build. Rollback-only database tests passed for vacancy metadata and persisted decision safeguards. Signed-in mobile rendering and Android device behavior have not been verified.
