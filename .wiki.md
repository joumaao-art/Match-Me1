# Project Summary
MatchMe is an AI-driven recruitment platform that matches job seekers and employers using swipe-style compatibility, then drives hiring through evaluations, messaging, notifications, analytics, and measurable outcomes. It delivers these capabilities via reusable, strongly bounded “Platform Engines” so experiences stay secure, observable, testable, and continuously improvable across web and mobile.

# Project Module Description
## Platform engine interaction model (enterprise)
- Defines the official networking protocol for all Platform Engines, including:
  - Strict dependency/layer hierarchy and explicit allowed vs forbidden dependencies between engine domains
  - Communication methods (public APIs, published events, contracts, dependency injection, queues, webhooks, shared interfaces)
  - Engine contracts (purpose, APIs, events published/consumed, configuration, dependencies, versioning, docs, health, metrics)
  - Synchronous vs asynchronous expectations
  - Event architecture requirements (immutable events; required fields such as correlation ID, tenant/user IDs, versioning, retry metadata)
  - Event lifecycle stages and observability requirements
  - Orchestrator responsibilities (platform, workflow, AI, business capability, journey, platform fabric)
  - Resilience standards (standardized results, error propagation, retry limits, circuit breakers, timeouts + fallbacks)
  - Governance standards (semantic versioning, deprecation policy, dependency registry integration, platform validation checks)
- Adds the official recommendation for a Platform Dependency Intelligence Engine to detect circular dependencies, architecture drift, and high coupling.

## Platform Engine SDK & Extension Framework
- Establishes the official SDK standards that every Platform Engine must follow to be consistent, modular, extensible, discoverable, observable, testable, secure, and future-proof.
- Treats Platform Engines as products (not utilities), so they present a consistent engineering experience across teams.
- Requires a standardized engine structure (fixed folder layout) including manifest, typed APIs, events, config, validators, errors, constants, metrics, health, lifecycle, permissions, telemetry, docs, examples, and tests/mocks/fixtures.
- Requires an engine manifest with complete registration metadata (engine identity, version/status, dependencies, public APIs, published/consumed events, configuration schema, permissions, health/metrics, docs, licensing/support, roadmap).
- Enforces a complete lifecycle with hooks for initialization, configuration, start/ready, pause/resume, config reload, shutdown/destroy, health checks, upgrade/rollback.
- Standardizes public API surface (commands/queries/configuration/events/status/metrics/health/capabilities) and forbids exposing internals.
- Standardizes event standards and event payload requirements (timestamp, correlation ID, tenant ID, engine version, environment).
- Enforces configuration standards (environment/runtime/tenant/feature flags/defaults/overrides) with validation and no code-required config changes.
- Enforces dependency declaration and bans circular dependencies; dependency injection is mandatory (no direct engine instantiation).
- Adds extension points and a plugin framework with isolation so extensions can add capabilities without modifying core engine code.
- Adds an extension marketplace recommendation (engine/plugins + UI/workflow/AI/provider integrations) with strict security isolation and centralized governance (install/enable/configure/monitor/upgrade/disable/uninstall/rollback).

# Technology Stack
- Frontend: Vite, React, TypeScript, Tailwind CSS
- Mobile: React Native, Expo
- Backend: Supabase, Node.js, PostgreSQL
- State Management: React Context API, Zustand
- Internationalization: i18next

# Usage
1. Install dependencies:
   - Run `pnpm install` in `app/frontend`
2. Build the web app:
   - Run `pnpm run build` in `app/frontend`
3. Run:
   - Web: Run `pnpm run start` in `app/frontend`
   - Mobile: Run `expo start` in `app/mobile`
