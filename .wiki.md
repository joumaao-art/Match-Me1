# Project Summary
MatchMe is an enterprise recruiting platform that matches job seekers and hiring teams using swipe-style compatibility plus AI, then completes recruiting end-to-end through governed workflows with messaging/notifications and analytics for measurable hiring outcomes. All traffic is standardized via a single governed Enterprise API Gateway and asynchronous communication is standardized via a governed Enterprise Event Platform (events, webhooks, and streaming).

# Project Module Description
- Platform Reference Implementation: Canonical blueprint for composing platform layers (experience engines, workflow/business/AI/security engines, infrastructure/operations), including core journeys, governance assets, operational conventions, and deployment/disaster recovery guidance.
- Enterprise Data Platform Specification: Enterprise data architecture covering storage, organization, governance, security, quality, lifecycle, accessibility, integration, and AI-readiness metadata (including multi-tenant/RLS and analytics/search architectures).
- Backup, Recovery & Disaster Recovery: Business continuity strategy including backup classification/types/frequency, restore operations, recovery objectives (RTO/RPO), recovery levels, disaster scenarios, validation/testing, and recovery security/audit requirements.
- Search & Indexing Architecture: Search platform definition including tenant/permission-aware security, ranking/filtering, index lifecycle/update strategy, APIs, analytics, and AI search readiness/performance targets.
- Canonical Entity Model: Authoritative platform-wide business entity definitions with versioned/documented relationships and validation rules.
- Relationship & Domain Modeling: Bounded domains, relationship types, aggregates, ownership, cardinality, lifecycle/cascade rules, cross-domain communication rules, and relationship registry/validation process.
- Database Standards & Naming Conventions: Official database engineering standards for schemas/tables/columns/constraints/indexes/views/functions/triggers and migrations, including security/audit/documentation/validation expectations.
- Multi-Tenant & Row-Level Security: Tenant hierarchy, resource ownership, visibility levels, row-level security requirements, and centralized security-resolution inherited by tables/entities/APIs/AI/search/analytics.
- Analytics & Reporting Data Platform: Governed, tenant-aware analytics architecture transforming event/operational data into versioned metrics/reports/dashboards/forecasts/AI insights via shared pipeline and registries.
- Data Governance, Quality & Compliance: Governance framework enforcing ownership/stewardship, classification and metadata/lineage standards, measurable quality, compliance/privacy/retention controls, and an automated governance requirement across datasets and workflows.
- Data SDK, Schemas & Migration Framework: Official Data SDK conventions plus schema lifecycle/versioning, compatibility rules, data contract standards, migration framework (validation, rollback, testing), and evolution governance via centralized registries.
- Enterprise Data Reference Implementation: Official implementation blueprint for the MatchMe Enterprise Data Platform, including reference data flows, lifecycle/state transitions, repository pattern rules, integration patterns, operational + disaster recovery blueprints, and enterprise reference registries.
- Enterprise API Platform Specification: Official Enterprise API Platform architecture defining API-as-product philosophy, cross-platform API stack, domain taxonomy, standards (naming/HTTP/responses/errors/pagination/filtering/sorting), security/versioning/lifecycle rules, documentation & validation requirements, and API registries.
- Prompt 6 Part 3 — Authentication, Authorization & API Security: Standards for authentication methods, token/session/session revocation, centralized authorization and permission resolution, API security controls (rate limiting, threat protection, encryption, validation), auditing, testing, compliance, and required platform-wide enforcement plus security governance registries.
- Prompt 6 Part 4 — API Contracts, Schemas & Validation: Enterprise standards for versioned API contracts, request/response schemas, validation, compatibility, deterministic serialization, OpenAPI/JSON-schema generation, consumer compatibility/testing, and governance registries for contracts/schemas/validation rules/enums/OpenAPI/consumers/webhooks/events.
- Prompt 6 Part 5 — API Gateway, Routing & Traffic Management: Defines the single entry-point gateway that enforces authentication/authorization, validates requests, performs version/tenant routing, applies caching/compression, handles resilience (rate limiting, circuit breakers, retry/timeout), orchestrates routing/load-balancing/service discovery, and emits gateway events into governance/analytics registries.
- Prompt 6 Part 6 — Event APIs, Webhooks & Streaming: Enterprise standards for governed asynchronous communication: immutable/versioned event model, event contracts, event bus capabilities (publish/subscribe/routing/retry/replay/DLQ/version compatibility/filtering), webhook registration/delivery/security/retries, and streaming APIs (SSE/WebSockets) with event lifecycle, observability, validation, and governance registries.
- Prompt 6 Part 7 — API Lifecycle, Versioning & Compatibility: Enterprise standards for API lifecycle stages, semantic versioning, compatibility rules, deprecation/sunset/retirement policies, release process, rollout strategies, compatibility testing, version monitoring, and required governance registries (including an API Evolution Intelligence Engine recommendation).
- Prompt 6 Part 8 — Developer Experience, SDKs & Documentation: Enterprise developer portal, SDK standards and generation, documentation standards, sandbox/mock/testing tooling, developer analytics, AI-friendly developer documentation, and governance registries for DX artifacts.

# Technology Stack
- Frontend: Vite, React, TypeScript, Tailwind CSS
- Mobile: React Native, Expo
- Backend: Supabase, Node.js, PostgreSQL
- State Management: React Context API, Zustand
- Internationalization: i18next

# Usage
1. Install dependencies (web):
   - Run `pnpm install` in `app/frontend`
2. Build the web app:
   - Run `pnpm run build` in `app/frontend`
3. Run:
   - Web: Run `pnpm run start` in `app/frontend`
   - Mobile: Run `expo start` in `app/mobile`
