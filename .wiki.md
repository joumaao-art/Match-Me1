# Project Summary

MatchMe is an enterprise recruiting platform that connects job seekers and hiring teams through swipe-based matching, career intelligence, and AI-assisted recruiting workflows. It supports authentication, onboarding, messaging, hiring pipelines, interviews, offers, analytics, employer operations, and English/Arabic localization.

Recent work fixes cross-account onboarding progress leakage. Onboarding state is now checked against the authenticated user, and the client store resets when the signed-in user changes or signs out. New users without their own saved progress start at Welcome; returning users can resume from their saved state. Signup and authentication flows were not broadly refactored.

# Project Module Description

- **Authentication and routing:** Supports public authentication and guarded Job Seeker and Company routes.
- **Job Seeker onboarding:** Maintains a canonical step registry with stable step IDs and restores progress from server state, then valid user-owned client state, then a Welcome fallback.
- **Account isolation:** Rejects locally persisted onboarding state owned by another user and resets onboarding state on sign-out or user changes.
- **Progress and destination resolution:** Tracks completed or skipped steps and resolves the next incomplete step without using profile completeness as onboarding progress.
- **Localization:** Supports English and Arabic, including RTL layouts.
- **Engineering language governance:** Provides English-language engineering guidance and a source-language validation check.
- **Runtime verification:** Includes a browser test for onboarding account isolation and existing authentication and navigation diagnostics.

# File Description Inventory

- `app/frontend/src/lib/onboarding-engine.ts`: Defines the onboarding steps and hydrates user-owned progress, falling back to Welcome when no valid progress exists.
- `app/frontend/src/App.tsx`: Resets onboarding state on sign-out and when the authenticated user changes.
- `app/frontend/scripts/runtime-onboarding-isolation.mjs`: Exercises account isolation, including a new account starting at Welcome after another account has advanced or completed onboarding.
- `app/frontend/scripts/check-cjk-engineering-text.mjs`: Checks engineering-controlled files for unintended CJK characters.
- `app/frontend/packages/shared/src/i18n/en.ts`: English product translations.
- `app/frontend/packages/shared/src/i18n/ar.ts`: Arabic translations and RTL content.
- `app/frontend/docs/enterprise/*.md`: Enterprise architecture, governance, workflow, and language-policy documentation.

# Technology Stack

- **Frontend:** Vite, React, TypeScript, Tailwind CSS
- **Mobile:** React Native, Expo
- **Backend:** Supabase, Node.js, PostgreSQL
- **State management:** React Context API, Zustand
- **Authentication:** Supabase Auth with email, OAuth, and phone OTP
- **Internationalization:** i18next with English and Arabic/RTL support
- **Workspace:** pnpm monorepo
- **Validation:** TypeScript, ESLint, production builds, browser harnesses, and language scanning

# Usage

1. Install frontend dependencies:

   ```bash
   cd app/frontend
   pnpm install
   ```

2. Start the frontend:

   ```bash
   pnpm run start
   ```

3. Build the production frontend:

   ```bash
   pnpm run build
   ```

4. Run the mobile application:

   ```bash
   cd app/mobile
   expo start
   ```

5. Run language validation:

   ```bash
   cd app/frontend
   pnpm run check:language
   ```

6. Run onboarding isolation and Job Seeker navigation diagnostics:

   ```bash
   cd app/frontend
   node scripts/runtime-onboarding-isolation.mjs
   node scripts/runtime-seeker-navigation.mjs
   node scripts/runtime-seeker-account-states.mjs
   ```

7. Run authentication and signup diagnostics:

   ```bash
   cd app/frontend
   node scripts/runtime-auth-matrix.mjs
   node scripts/runtime-signup-e2e.mjs
   ```

8. Configure Supabase providers, email confirmation, redirect settings, session persistence, database policies, and required environment variables before provider-specific testing.
