# Project Summary

MatchMe is a bilingual recruiting marketplace connecting job seekers with employers. Job seekers discover vacancies, manage applications, save preferences, and maintain professional profiles; companies publish vacancies and review applicants. Admin tools support marketplace operations.

The Job Seeker experience is delivered by the responsive web application. The mobile project retains its Expo/React Native hybrid architecture: a native shell loads the canonical MatchMe website in a WebView and provides native safe areas, Android Back handling, sharing, and job-link continuation. It is not a native implementation of the marketplace screens. Native build success, device acceptance, and store readiness have not been verified.

The Swipe experience provides deterministic, Supabase-backed skill recommendations. VIA Premium offers monthly and yearly plans; paid access depends on complete Stripe webhook configuration and verified sandbox transactions. Native purchases remain disabled pending approved store billing.

# Project Module Description

- **Authentication and routing:** Signup, login, verification, role-based routes, shared-job authentication recovery, and Supabase sign-out.
- **Onboarding:** Mobile and desktop Job Seeker onboarding, validation, account-isolated draft recovery, and confirmed mobile date entry.
- **Job Seeker Dashboard:** Search, application categories and statuses, application details, saved jobs, and skipped-job reconsideration.
- **Swipe and vacancy matching:** Vacancy decisions, preference and eligibility ranking, credits access, and selected-card navigation. Improve My Match provides deterministic skill recommendations, individual skill confirmation, canonical profile saving, and matching-score recalculation.
- **Skill Match analysis:** Authenticated Supabase-backed recommendations with private caching, rate limits, ownership checks, deduplicated saves, and deterministic fallback behavior. No external AI service or API key is used.
- **Responsive mobile experience:** Responsive web layouts, resize-stable expanded content, and accessible bottom navigation.
- **Native app shell:** Expo/React Native WebView container for the canonical website, with safe areas, Android Back handling, Share, job-link continuation, and an origin-validated appearance bridge. Android device behavior and native appearance remain unverified.
- **Appearance settings:** Job Seeker Light Mode, Dark Mode, and System Default with account-scoped persistence and local caching. The outdated regression assertion was corrected without undoing the Personal-page scrolling fix. All 30 appearance checks passed, including isolated checks for modes, owner isolation, and failed-save handling. Native device verification is still blocked.
- **Personal profile and skills:** Mobile and desktop editing with shared validation and backend-confirmed saves. Compensation is optional and private.
- **Professional history:** Experience, Education, and Certification editing. Mobile date selections require confirmation; Current/Present options are retained.
- **Saved Preferences:** Mobile and desktop preference interfaces with persistence across logout and login.
- **Profile, account, and resume:** Account overview, private CV access, canonical profile data, and bilingual VIA Resume PDF generation. CV validation and account-change safeguards were strengthened around uploads, account reads, and signed links.
- **Logout:** Confirmation-based Supabase sign-out, account-cache cleanup, error handling, and welcome-page redirect. Persisted user data is retained.
- **Support and settings:** FAQ, persisted issue reporting, and Appearance settings. Unconfigured support providers and unavailable account operations are not presented as functional.
- **Company marketplace:** Company profiles, private logo storage, vacancy drafts and publication, dashboard counts, and applicant review.
- **Applications and matches:** Company review decisions update application statuses and seeker matches.
- **VIA Premium and payments:** Monthly and yearly plans, subscription management, credit access, Stripe checkout, server-side catalog validation, and verified webhook entitlement updates. Subscription logic was preserved.
- **Shared job links:** Stable vacancy IDs support web landing pages and authentication recovery. Android App Links require deployment configuration.
- **Profiles, messaging, and localization:** Shared profile and history records, existing messaging, English and Arabic translations, and Company/Admin portals. Live chat and unread-count consistency are not established.
- **Native release readiness:** An English developer handoff documents completed work and remaining external tasks. EAS configuration, secure native sessions, OAuth callbacks, file handling, permissions, notifications, billing approval, signing, and real-device testing remain external or blocked. Native compatibility and store readiness are not claimed.

# Technology Stack

- **Frontend:** React, TypeScript, Vite, Tailwind CSS
- **Native shell:** Expo and React Native with a shared-screen WebView container
- **Backend and data:** Supabase, Node.js, PostgreSQL, Supabase Edge Functions
- **Authentication:** Supabase Auth
- **State management:** React Context API, Zustand
- **Skill recommendations:** Deterministic Supabase-backed provider; no external AI integration
- **Payments:** Stripe checkout and webhook integration with server-side verification
- **PDFs and fonts:** Browser PDF generation and Amiri Arabic font asset
- **Internationalization:** i18next, English and Arabic/RTL
- **Workspace:** pnpm monorepo
- **Validation:** TypeScript, ESLint, production builds, contract checks, and rollback-only database tests
- **Native builds:** EAS is a possible external build service; successful MatchMe builds remain unverified.

# Usage

1. Install frontend dependencies:

   ```bash
   cd app/frontend
   pnpm install
   ```

2. Start the frontend:

   ```bash
   pnpm run start
   ```

3. Build the production frontend:

   ```bash
   pnpm run build
   ```

4. Validate translations:

   ```bash
   pnpm run check:language
   ```

5. Run mobile, appearance, Personal scrolling, and handoff checks:

   ```bash
   node scripts/mobile-compatibility-contract.mjs
   node scripts/seeker-appearance-contract.mjs
   node scripts/personal-scroll-contract.mjs
   node scripts/mobile-handoff-contract.mjs
   ```

6. Run Skill Match and other feature checks as needed:

   ```bash
   node scripts/skill-match-contract.mjs
   node scripts/mobile-date-confirmation-contract.mjs
   node scripts/mobile-icon-contract.mjs
   node scripts/desktop-parity-contract.mjs
   node scripts/seeker-navigation-contract.mjs
   node scripts/live-marketplace-contract.mjs
   node scripts/via-premium-contract.mjs
   ```

7. Configure Supabase and apply required migrations for profiles, private CV storage, Personal categories, account settings, and Skill Match.

8. Deploy required Supabase functions. Skill recommendations do not require an external AI service or API key. Configure Stripe secrets and webhook deployment separately, and verify a sandbox transaction before enabling paid access.

9. For native release work, follow `app/frontend/docs/EXPO_NATIVE_DEVELOPER_HANDOFF.md`. EAS configuration, platform identifiers, signing, provider integrations, native authentication and file handling, permissions, notifications, billing approval, and real-device testing require external work. Native compatibility and store readiness are not established.

10. The supported follow-up passed 206 source, unit, and DOM checks, plus web lint and production build. The available rendering check showed the guest desktop page; authenticated Settings and native behavior were not verified.
