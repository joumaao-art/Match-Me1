# Project Summary

MatchMe is a recruiting marketplace connecting job seekers with employers. Job seekers discover vacancies, manage applications, save preferences, and maintain professional profiles; companies publish vacancies and review applicants. Admin tools support marketplace operations. The product supports English and Arabic and uses Supabase for account and marketplace data.

The mobile Job Seeker experience includes onboarding, a Dashboard, vacancy discovery, Saved Preferences, Profile and skills editing, subscription overview, private CV access, and VIA Resume PDF generation. Mobile Profile now also offers a confirmation-based Logout flow. Logout signs out through Supabase, clears local account caches without deleting persisted user data, and redirects to the welcome page. Support includes FAQ content and persisted issue reporting; unavailable channels and actions are not presented as functional.

VIA Premium offers monthly and yearly plans. Paid access requires complete Stripe webhook configuration and a verified sandbox transaction; native purchases remain disabled pending approved store billing.

# Project Module Description

- **Authentication and routing:** Signup, login, verification, role-based routes, shared-job authentication recovery, and shared Supabase sign-out.
- **Mobile onboarding:** Eleven onboarding steps with account-isolated draft recovery, validation, and derived birthday age display.
- **Job Seeker Dashboard:** Mobile navigation, search, application categories and statuses, application details, saved jobs, and skipped-job reconsideration.
- **Vacancy discovery and decisions:** Preference-aware matching, eligibility guidance, and persisted actions with ownership, duplicate, credit, and expiry safeguards.
- **Saved Preferences:** Mobile preferences UI and persistence across logout and login.
- **Mobile Profile and resume:** Account overview, personal and skills editing, subscription overview, private CV access, and bilingual VIA Resume PDF generation.
- **Mobile logout:** Confirmation dialog, English/Arabic text, Supabase sign-out, local account-cache cleanup, error handling, and welcome-page redirect. Persisted user data and desktop, Company, and Admin flows remain unchanged.
- **Support and settings:** FAQ and persisted issue reporting. Unconfigured support providers and unavailable account operations are not represented as functional.
- **Company marketplace:** Company profiles, private logo storage, vacancy drafts and publication, dashboard counts, and applicant review.
- **Applications and matches:** Company review decisions update application statuses and seeker matches.
- **VIA Premium and credits:** Credit access, monthly and yearly plan selection, subscription management, and server-derived Premium eligibility.
- **Payments and entitlements:** Stripe checkout and verification use server-side catalog validation; subscription lifecycle updates require verified webhook signatures.
- **Shared job links:** Stable vacancy IDs support web landing pages and authentication recovery. Android App Links require deployment configuration.
- **Profiles, messaging, and localization:** Shared profile and history records, existing messaging, English/Arabic translations, and Company/Admin portals. Live chat and unread-count consistency are not established.
- **Swipe Profile Completion:** Read-only informational indicator with its existing design, calculation, and automatic updates; desktop layout remains unchanged.

# Technology Stack

- **Frontend:** React, TypeScript, Vite, Tailwind CSS
- **Native app:** Expo and React Native with a shared-screen WebView container
- **Backend and data:** Supabase, Node.js, PostgreSQL
- **Authentication:** Supabase Auth
- **State management:** React Context API, Zustand
- **Payments:** Stripe checkout and webhook integration with server-side verification
- **PDFs and fonts:** Browser PDF generation and Amiri Arabic font asset
- **Internationalization:** i18next, English and Arabic/RTL
- **Workspace:** pnpm monorepo
- **Validation:** TypeScript, ESLint, production builds, contract checks, and rollback-only database tests

# Usage

1. Install frontend dependencies:

   ```bash
   cd app/frontend
   pnpm install
   ```

2. Start the frontend:

   ```bash
   pnpm run start
   ```

3. Build the production frontend:

   ```bash
   pnpm run build
   ```

4. Validate translations:

   ```bash
   pnpm run check:language
   ```

5. Run relevant contract checks:

   ```bash
   node scripts/live-marketplace-contract.mjs
   node scripts/via-premium-contract.mjs
   node scripts/savings-preferences-contract.mjs
   node scripts/mobile-swipe-contract.mjs
   node scripts/seeker-navigation-contract.mjs
   node scripts/mobile-dashboard-contract.mjs
   node scripts/mobile-onboarding-contract.mjs
   node scripts/mobile-profile-contract.mjs
   node scripts/mobile-logout-contract.mjs
   ```

6. Configure Supabase and apply the required migrations, including `022_mobile_profile.sql`, for Profile persistence and private CV storage.

7. Deploy payment functions with the required Stripe secrets. Complete webhook configuration and verify a sandbox transaction before enabling paid access. Android App Links require deployment-specific domain association, package and signing fingerprints, and device/build access. Native purchases remain disabled pending approved store billing.

8. Logout validation passed 80 targeted checks, TypeScript, lint, and production build. Authenticated viewer acceptance remains unverified: all 10 manual checks were blocked because the viewer exposed only the guest page.
