# Project Summary
MatchMe is an enterprise recruiting platform that matches job seekers and hiring teams using swipe-style compatibility plus AI, then completes recruiting end-to-end through governed workflows (messaging/notifications) and measurable analytics. All client traffic is standardized via a single governed Enterprise API Gateway, and asynchronous communication is standardized via a governed Enterprise Event Platform (events, webhooks, streaming).

# Project Module Description
- Platform Reference Implementation: Canonical blueprint for composing platform layers (experience, workflow/business/AI/security engines, infrastructure/operations), including journeys, governance assets, and deployment/disaster recovery guidance.
- Enterprise Data Platform Specification: Enterprise data architecture covering storage, organization, governance, security, quality, lifecycle, accessibility, integration, and AI-readiness metadata (multi-tenant/RLS and analytics/search architectures).
- Backup, Recovery & Disaster Recovery: Business continuity strategy including backup classification/types/frequency, restore operations, recovery objectives (RTO/RPO), recovery levels, disaster scenarios, validation/testing, and recovery security/audit requirements.
- Search & Indexing Architecture: Search platform definition including tenant/permission-aware security, ranking/filtering, index lifecycle/update strategy, APIs, and AI search readiness/performance targets.
- Canonical Entity Model: Authoritative platform-wide business entity definitions with versioned/documented relationships and validation rules.
- Relationship & Domain Modeling: Bounded domains, relationship types, aggregates, ownership, cardinality, lifecycle/cascade rules, and cross-domain communication rules (with relationship registry/validation).
- Database Standards & Naming Conventions: Official engineering standards for schemas/tables/columns/constraints/indexes/views/functions/triggers and migrations, including security/audit/documentation/validation expectations.
- Multi-Tenant & Row-Level Security: Tenant hierarchy, resource ownership/visibility, row-level security requirements, and centralized security-resolution inherited by tables/entities/APIs/AI/search/analytics.
- Analytics & Reporting Data Platform: Governed, tenant-aware analytics architecture transforming event/operational data into versioned metrics/reports/dashboards/forecasts/AI insights via shared pipeline and registries.
- Data Governance, Quality & Compliance: Governance framework enforcing ownership/stewardship, classification/metadata/lineage standards, measurable quality, compliance/privacy/retention controls, and automated governance requirements.
- Data SDK, Schemas & Migration Framework: Data SDK conventions plus schema lifecycle/versioning, compatibility rules, data contract standards, and migration framework (validation/rollback/testing) with centralized evolution governance.
- Enterprise Data Reference Implementation: Official reference blueprint for the enterprise data platform, including reference data flows, lifecycle/state transitions, integration patterns, operational + disaster recovery blueprints, and enterprise reference registries.
- Enterprise API Platform Specification: API-as-product architecture defining standards (naming/HTTP/responses/errors/pagination/filtering/sorting), security/versioning/lifecycle rules, documentation/validation requirements, and API registries.
- Prompt 6 Part 3 — Authentication, Authorization & API Security: Standards for authentication/token/session revocation, centralized authorization and permission resolution, API security controls (rate limiting, threat protection, encryption, validation), auditing/testing/compliance, and required platform-wide enforcement.
- Prompt 6 Part 4 — API Contracts, Schemas & Validation: Versioned API contract standards, request/response schemas, validation, compatibility, deterministic serialization, OpenAPI/JSON-schema generation, and governance registries.
- Prompt 6 Part 5 — API Gateway, Routing & Traffic Management: Single governed entry-point gateway enforcing auth/z validation, tenant/version routing, caching/compression, resilience, orchestration/service discovery, and event emission for governance/analytics.
- Prompt 6 Part 6 — Event APIs, Webhooks & Streaming: Governed asynchronous communication with immutable/versioned event model, contracts, bus capabilities, webhook delivery/security/retries, and streaming APIs with observability/validation/governance.
- Prompt 6 Part 7 — API Lifecycle, Versioning & Compatibility: API lifecycle stages, semantic versioning, compatibility/deprecation/sunset/retirement policies, release/rollout process, and governance registries.
- Prompt 6 Part 8 — Developer Experience, SDKs & Documentation: Developer portal/SDK standards, documentation standards, sandbox/mock/testing tooling, developer analytics, AI-friendly documentation, and governance registries for DX artifacts.
- Prompt 6 Part 9 — API Governance, Observability & Performance: Enterprise governance for APIs, mandatory observability pillars, performance standards/SLOs/SLAs, alerting/dashboards/cost monitoring, audit/compliance, and continuous optimization.
- Prompt 7 — Frontend Architecture (Web + Mobile Unified): Unified frontend architecture defining a consistent, scalable design system/component architecture/shared logic approach across Web, Mobile, and Admin tools.

# Technology Stack
- Frontend: Vite, React, TypeScript, Tailwind CSS
- Mobile: React Native, Expo
- Backend: Supabase, Node.js, PostgreSQL
- State Management: React Context API, Zustand
- Internationalization: i18next

# Usage
1. Install dependencies (web):
   - Run `pnpm install` in `app/frontend`
2. Build the web app:
   - Run `pnpm run build` in `app/frontend`
3. Run:
   - Web: Run `pnpm run start` in `app/frontend`
   - Mobile: Run `expo start` in `app/mobile`
