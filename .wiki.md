# Project Summary
MatchMe is an enterprise recruiting platform that matches job seekers and hiring teams using swipe-style compatibility plus AI, then executes end-to-end recruiting through governed workflows with messaging/notifications and analytics that support measurable hiring outcomes.

# Project Module Description
- Platform Reference Implementation (Prompt 4C): Canonical end-to-end blueprint for composing platform layers (experience engines, workflow/business/AI/security engines, infrastructure/operations), including core journeys, governance assets, operational conventions, and deployment/disaster recovery guidance.
- Enterprise Data Platform Specification (Prompt 5): Enterprise data architecture covering storage, organization, governance, security, quality, lifecycle, accessibility, integration, and AI-readiness metadata (including multi-tenant/RLS and analytics/search architectures).
- Backup, Recovery & Disaster Recovery (Prompt 5 Part 9): Business continuity strategy including backup classification/types/frequency, restore operations, recovery objectives (RTO/RPO), recovery levels, disaster scenarios, validation/testing, and recovery security/audit requirements.
- Search & Indexing Architecture (Prompt 5 Part 6): Search platform definition including tenant/permission-aware security, ranking/filtering, index lifecycle/update strategy, APIs, analytics, and AI search readiness/performance targets.
- Canonical Entity Model (Prompt 5 Part 2): Authoritative platform-wide business entity definitions with versioned/documented relationships and validation rules.
- Relationship & Domain Modeling (Prompt 5 Part 3): Bounded domains, relationship types, aggregates, ownership, cardinality, lifecycle/cascade rules, cross-domain communication rules, and relationship registry/validation process.
- Database Standards & Naming Conventions (Prompt 5 Part 4): Official database engineering standards for schemas/tables/columns/constraints/indexes/views/functions/triggers and migrations, including security/audit/documentation/validation expectations.
- Multi-Tenant & Row-Level Security (Prompt 5 Part 5): Tenant hierarchy, resource ownership, visibility levels, row-level security requirements, and centralized security-resolution inherited by tables/entities/APIs/AI/search/analytics.
- Analytics & Reporting Data Platform (Prompt 5 Part 7): Governed, tenant-aware analytics architecture transforming event/operational data into versioned metrics/reports/dashboards/forecasts/AI insights via shared pipeline and registries.
- Data Governance, Quality & Compliance (Prompt 5 Part 8): Governance framework enforcing ownership/stewardship, classification and metadata/lineage standards, measurable quality, compliance/privacy/retention controls, and an automated governance requirement across datasets and workflows.
- Data SDK, Schemas & Migration Framework (Prompt 5 Part 10): Official Data SDK conventions plus schema lifecycle/versioning, compatibility rules, data contract standards, migration framework (validation, rollback, testing), and evolution governance via centralized registries.

# Technology Stack
- Frontend: Vite, React, TypeScript, Tailwind CSS
- Mobile: React Native, Expo
- Backend: Supabase, Node.js, PostgreSQL
- State Management: React Context API, Zustand
- Internationalization: i18next

# Usage
1. Install dependencies (web):
   - Run `pnpm install` in `app/frontend`
2. Build the web app:
   - Run `pnpm run build` in `app/frontend`
3. Run:
   - Web: Run `pnpm run start` in `app/frontend`
   - Mobile: Run `expo start` in `app/mobile`
