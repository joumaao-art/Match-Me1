# Project Summary

MatchMe is an enterprise recruiting platform connecting job seekers with employers through job discovery, applications, career tools, and recruiting workflows. It supports Job Seeker and Company accounts, onboarding, messaging, interviews, offers, analytics, and English/Arabic localization.

The Job Seeker experience includes a consolidated Profile for professional details, resume management, experience, education, certificates, and languages. Recent UX changes add a Profile Preferences entry, searchable role selection, multi-select employment preferences, a Profile phone-number field, clickable Dashboard destinations, and pass-only Undo on Discover.

Some integrations remain incomplete: Preferences are stored in browser storage rather than the database; onboarding and signup have not been migrated to the new shared preference and phone components; preference signals are not wired into matching, search, candidate discovery, or Career Graph. The production build and lint passed, but authenticated UI, mobile, desktop, and RTL behavior were not verified in the App Viewer.

# Project Module Description

- **Authentication and routing:** Provides authentication and guarded Job Seeker and Company routes. Existing Preferences, Applications, and Matches routes remain available even though some standalone navigation entries have been removed.
- **Job Seeker navigation:** Preferences, Applications, and Matches are removed from the desktop sidebar. Applications is also removed from the mobile bottom bar. Resume and Certificates remain in navigation and were not removed in this update.
- **Profile:** Consolidates professional details and resume management. Includes a Preferences entry that opens the canonical Preferences experience and a searchable country calling-code phone field. The new phone field is not yet shared with signup.
- **Preferences:** Provides searchable, multi-select preferred roles and employment options. Suggestions are derived from available skills, job titles, and education; users must select suggestions themselves. Older free-text roles and single employment types are converted in the browser. Preferences currently use per-user browser storage, not database persistence.
- **Discover:** Replaces the Save control beside Share with a pass-only Undo action. Undo is unavailable when there is no eligible pass and records an analytics event. A Preferences shortcut opens the shared Preferences form in a bottom sheet.
- **Dashboard:** Makes statistic cards keyboard-accessible navigation gateways. Applications, Matches, Interviews, and Profile Views lead to their respective destinations. Counts currently use sample data.
- **Matching and Career Graph:** A preference scoring helper exists, but selected preferences are not yet integrated into recommendation ranking, vacancy matching, candidate discovery, or Career Graph. Matching still uses sample profile data.
- **Experience, education, and languages:** Experience supports standardized employment options, date ranges, chronological sorting, and overlapping-period calculations. Education includes certificates and supports current study. Language proficiency uses Fluent and Native Speaker options.
- **Location data and localization:** Country data and country-specific city files support profile location controls. Updated profile and preference copy is available in English and Arabic; RTL behavior has not been validated for this update.

# Technology Stack

- **Frontend:** React, TypeScript, Vite, Tailwind CSS
- **Mobile:** React Native, Expo
- **Backend and data:** Supabase, Node.js, PostgreSQL
- **State management:** React Context API, Zustand
- **Authentication:** Supabase Auth, including email, OAuth, and phone OTP
- **Internationalization:** i18next, English and Arabic/RTL
- **Workspace:** pnpm monorepo
- **Validation:** TypeScript, ESLint, production builds, browser diagnostics, and language scanning

# Usage

1. Install frontend dependencies:

   ```bash
   cd app/frontend
   pnpm install
   ```

2. Start the frontend:

   ```bash
   pnpm run start
   ```

3. Build the production frontend:

   ```bash
   pnpm run build
   ```

4. Start the mobile application:

   ```bash
   cd app/mobile
   expo start
   ```

5. Run language validation:

   ```bash
   cd app/frontend
   pnpm run check:language
   ```

6. Run onboarding isolation and Job Seeker diagnostics:

   ```bash
   cd app/frontend
   node scripts/runtime-onboarding-isolation.mjs
   node scripts/runtime-seeker-navigation.mjs
   node scripts/runtime-seeker-account-states.mjs
   ```

7. Run authentication and signup diagnostics:

   ```bash
   cd app/frontend
   node scripts/runtime-auth-matrix.mjs
   node scripts/runtime-signup-e2e.mjs
   ```

8. Configure Supabase providers, redirects, session persistence, database policies, and required environment variables before provider-specific testing. Preference data currently resides in browser storage. Apply and verify database migrations before relying on database-backed features.
