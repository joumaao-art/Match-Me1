# Project Summary

MatchMe is an enterprise recruiting marketplace connecting job seekers and employers through vacancy discovery, applications, profiles, messaging, and recruiting workflows. It supports Job Seeker, Company, and Admin experiences, with English and Arabic localization.

The live marketplace uses persisted Supabase data for Company profiles, vacancy drafts and publication, applicant review, and seeker activity. Job seekers can discover vacancies, apply, save jobs, and view persisted matches, credits, and profile completion. Company registration and profile updates report save errors rather than silently discarding them. No demo vacancies were added.

Recent validation passed TypeScript, lint, production build, 42 contract checks, and authenticated rollback-only database checks. Required signed-in browser acceptance for the full Company-to-seeker workflow has not been run; release readiness for that workflow remains unverified.

# Project Module Description

- **Authentication and routing:** Signup, login, verification, role-based routes, and shared-job authentication recovery.
- **Mobile onboarding:** Eleven semantic onboarding steps with account-isolated draft recovery, validation, and derived birthday age display.
- **Job Seeker experience:** Mobile Swipe, Dashboard, and Profile navigation. Dashboard activity uses persisted applications, matches, saves, credits, and profile completion.
- **Vacancy discovery and decisions:** Canonical vacancy records, deterministic ranking fallback, eligibility guidance, and persisted actions with ownership, duplicate, credit, and expiry safeguards.
- **Company marketplace:** Persisted Company profiles, private logo storage, dashboard counts, vacancy drafts, validated publication, and live applicant review.
- **Applications and matches:** Company review decisions drive application statuses and seeker matches.
- **Shared job links:** Stable vacancy IDs support web landing pages and authentication recovery. Android App Links still require deployment configuration.
- **Profiles and preferences:** Shared profile and history records, with preferences for roles, keywords, working styles, work types, and seniority.
- **Messaging, localization, and portals:** Existing messaging, English/Arabic translations, Company portal, and Admin portal remain available. Live chat and unread-count consistency are not established.

# Technology Stack

- **Frontend:** React, TypeScript, Vite, Tailwind CSS
- **Native app:** Expo and React Native, with a shared-screen WebView container
- **Backend and data:** Supabase, Node.js, PostgreSQL
- **Authentication:** Supabase Auth
- **State management:** React Context API, Zustand
- **Payments:** Stripe integration with server-side verification
- **Internationalization:** i18next, English and Arabic/RTL
- **Workspace:** pnpm monorepo
- **Validation:** TypeScript, ESLint, production builds, contract checks, and database integration tests

# Usage

1. Install frontend dependencies:

   ```bash
   cd app/frontend
   pnpm install
   ```

2. Start the frontend:

   ```bash
   pnpm run start
   ```

3. Build the production frontend:

   ```bash
   pnpm run build
   ```

4. Validate translations:

   ```bash
   pnpm run check:language
   ```

5. Run the marketplace, Swipe, navigation, and onboarding contracts:

   ```bash
   node scripts/live-marketplace-contract.mjs
   node scripts/mobile-swipe-contract.mjs
   node scripts/seeker-navigation-contract.mjs
   node scripts/mobile-onboarding-contract.mjs
   ```

6. Run available runtime diagnostics:

   ```bash
   node scripts/runtime-onboarding-isolation.mjs
   node scripts/runtime-seeker-navigation.mjs
   node scripts/runtime-seeker-account-states.mjs
   node scripts/runtime-auth-matrix.mjs
   node scripts/runtime-signup-e2e.mjs
   ```

7. Configure Supabase and apply the required migrations. Supply Stripe and location-provider credentials as needed. Android App Links require deployment-specific domain association, package and signing fingerprints, and device/build access.
