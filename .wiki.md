# Project Summary

MatchMe is a recruiting marketplace connecting job seekers with employers. Job seekers discover vacancies, manage applications, save preferences, and maintain professional profiles; companies publish vacancies and review applicants. Admin tools support marketplace operations. The product supports English and Arabic and uses Supabase for account and marketplace data.

The Job Seeker experience includes mobile and desktop workflows for onboarding, Dashboard, vacancy discovery, preferences, Profile and skills editing, subscriptions, private CV access, and VIA Resume PDF generation. Desktop-specific screens reuse canonical services and job actions, while mobile remains the product-authority baseline. The desktop sidebar is ordered Swipe, Dashboard, Profile, Subscription Overview, Preferences. Desktop Profile actions link to VIA Resume and Personal; duplicate Logout and subscription-card controls have been removed. Desktop Swipe no longer has Preferences controls. The sidebar footer remains, and mobile source is unchanged.

Mobile and desktop Profile editing share a canonical data model and save service for Identity, Contact, optional Current Compensation, and Gender. Existing profile data is preserved; Title and compensation are stored privately. Mobile and desktop logout use confirmation, Supabase sign-out, and local account-cache cleanup without deleting persisted user data.

VIA Premium offers monthly and yearly plans. Paid access requires complete Stripe webhook configuration and a verified sandbox transaction; native purchases remain disabled pending approved store billing.

# Project Module Description

- **Authentication and routing:** Signup, login, verification, role-based routes, shared-job authentication recovery, and shared Supabase sign-out.
- **Onboarding:** Mobile and desktop Job Seeker onboarding, validation, and account-isolated draft recovery.
- **Job Seeker Dashboard:** Mobile and desktop navigation, search, application categories and statuses, application details, saved jobs, and skipped-job reconsideration.
- **Desktop navigation:** Five-item sidebar for Swipe, Dashboard, Profile, Subscription Overview, and Preferences. Profile links to VIA Resume and Personal. Duplicate Profile actions and desktop Swipe Preferences controls have been removed.
- **Vacancy discovery and decisions:** Preference-aware matching, eligibility guidance, and persisted actions with ownership, duplicate, credit, and expiry safeguards.
- **Saved Preferences:** Mobile and desktop preference interfaces with persistence across logout and login.
- **Personal profile and skills:** Mobile and desktop editing for Identity, Contact, Current Compensation, Gender, and skills, using shared validation and backend-confirmed saves. Compensation is optional and private.
- **Profile, account, and resume:** Account overview, private CV access, and bilingual VIA Resume PDF generation. Mobile and desktop have dedicated account and resume interfaces.
- **Logout:** Confirmation-based mobile and desktop logout with Supabase sign-out, account-cache cleanup, error handling, and welcome-page redirect. Persisted user data is retained.
- **Support and settings:** FAQ and persisted issue reporting. Unconfigured support providers and unavailable account operations are not presented as functional.
- **Swipe and credits:** Mobile and desktop vacancy decisions, credits access, selected-card navigation, and read-only Profile Completion indicator.
- **Company marketplace:** Company profiles, private logo storage, vacancy drafts and publication, dashboard counts, and applicant review.
- **Applications and matches:** Company review decisions update application statuses and seeker matches.
- **VIA Premium and payments:** Monthly and yearly plans, subscription management, credit access, Stripe checkout, server-side catalog validation, and verified webhook entitlement updates.
- **Shared job links:** Stable vacancy IDs support web landing pages and authentication recovery. Android App Links require deployment configuration.
- **Profiles, messaging, and localization:** Shared profile and history records, existing messaging, English/Arabic translations, and Company/Admin portals. Live chat and unread-count consistency are not established.
- **Desktop parity evidence:** Feature matrix, baseline, and reports track desktop coverage, mobile preservation, navigation cleanup, known limitations, and blocked authenticated acceptance. No backend or data writes were made for the navigation cleanup.

# Technology Stack

- **Frontend:** React, TypeScript, Vite, Tailwind CSS
- **Native app:** Expo and React Native with a shared-screen WebView container
- **Backend and data:** Supabase, Node.js, PostgreSQL
- **Authentication:** Supabase Auth
- **State management:** React Context API, Zustand
- **Payments:** Stripe checkout and webhook integration with server-side verification
- **PDFs and fonts:** Browser PDF generation and Amiri Arabic font asset
- **Internationalization:** i18next, English and Arabic/RTL
- **Workspace:** pnpm monorepo
- **Validation:** TypeScript, ESLint, production builds, contract checks, and rollback-only database tests

# Usage

1. Install frontend dependencies:

   ```bash
   cd app/frontend
   pnpm install
   ```

2. Start the frontend:

   ```bash
   pnpm run start
   ```

3. Build the production frontend:

   ```bash
   pnpm run build
   ```

4. Validate translations:

   ```bash
   pnpm run check:language
   ```

5. Run relevant contract checks:

   ```bash
   node scripts/desktop-parity-contract.mjs
   node scripts/seeker-navigation-contract.mjs
   node scripts/live-marketplace-contract.mjs
   node scripts/via-premium-contract.mjs
   node scripts/savings-preferences-contract.mjs
   node scripts/mobile-swipe-contract.mjs
   node scripts/mobile-dashboard-contract.mjs
   node scripts/mobile-onboarding-contract.mjs
   node scripts/mobile-profile-contract.mjs
   node scripts/mobile-logout-contract.mjs
   node scripts/personal-information-contract.mjs
   ```

6. Configure Supabase and apply the required migrations, including `022_mobile_profile.sql` and `023_personal_categories.sql`, for Profile persistence, private CV storage, and Personal categories.

7. Deploy payment functions with the required Stripe secrets. Complete webhook configuration and verify a sandbox transaction before enabling paid access. Android App Links require deployment-specific domain association, package and signing fingerprints, and device/build access. Native purchases remain disabled pending approved store billing.

8. The desktop navigation cleanup passed 247 source/unit checks, TypeScript, lint, and build validation. Authenticated navigation, saving, checkout, and logout remain unverified because the viewer reached only the guest landing page.
