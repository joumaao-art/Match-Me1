# MATCHME — SUBSCRIPTION SAVINGS & SWIPE PREFERENCES REDESIGN

## Objective

Implement two targeted improvements to MatchMe:

1. Display subscription savings clearly on the VIA Premium subscription page.
2. Redesign the mobile Job Seeker Preferences page accessed through the Swipe page.

Preserve the existing MatchMe architecture, authentication, credits, AI Matching Engine, and shared preference data.

**Important requirements:**

- Apply the Preferences visual redesign to the mobile version only.
- Do not modify the desktop Preferences layout.
- Do not rebuild existing functionality unnecessarily.
- Use existing canonical taxonomies and database structures.
- Maintain English and Arabic localization.
- All Atoms Working Process updates and final reports must be in English only.
- The application name remains MatchMe. VIA Premium is the subscription product.

---

## PART 1 — VIA PREMIUM SUBSCRIPTION SAVINGS

### 1. Subscription Plans

Maintain the following subscription plans:

**Monthly**
- Price: $10/month.
- No Most Popular label.
- Display the savings as 0% if savings are shown for both plans.

**Yearly**
- Price: $100/year.
- Display the Most Popular label.
- Display the savings percentage prominently next to the Yearly plan.

### 2. Savings Calculation

Calculate the savings against the equivalent cost of paying monthly for 12 months.

Monthly cost:
$10 × 12 = $120/year.

Yearly cost:
$100/year.

Savings:
($120 − $100) ÷ $120 × 100 = 16.67%.

Display:

**Save 17%**

Use rounded whole-number percentage formatting for the UI.

Do not display misleading discounts or claim savings against an invented original price.

### 3. Subscription Page Layout

Maintain the heading:

**Unlimited applications with VIA Premium**

Show the plans as follows:

**Monthly — $10/month**

**Yearly — $100/year | Most Popular | Save 17%**

The Yearly subscription must remain selected by default.

Use a professional, subtle visual highlight for the selected Yearly plan.

Do not use excessive gradients, oversized badges, or promotional animations.

### 4. Subscription Footer

Keep:

"Subscription auto renews until cancelled"

Keep the button:

**Subscribe VIA Premium**

Ensure that:

- Monthly selection sends $10/month to checkout.
- Yearly selection sends $100/year to checkout.
- The selected billing interval is clearly displayed.
- The savings percentage updates from actual configured prices if pricing changes.
- Payment confirmation and subscription activation continue using the existing secure billing system.

Do not change any other subscription functionality.

# PART 2 — MOBILE SWIPE PREFERENCES REDESIGN

## 5. Scope

Redesign the Preferences page accessed from the Preferences icon in the top-right corner of the mobile Swipe page.

The Preferences page must be clean, compact, professional, and easy to navigate.

Remove unnecessary sections and controls from this mobile Preferences view.

**The page must contain only:**

1. MatchMe logo and Save icon.
2. Roles & Keywords.
3. Countries interested in job searching.
4. Job Type.
5. Work Style.
6. Level.

Do not add additional preference categories, introductory banners, large cards, or unrelated settings.

Preserve any existing preference data not displayed in this simplified view. Do not delete database fields merely because they are hidden from this page.

---

## 6. Preferences Header

At the top of the page:

**Top-left:** Official MatchMe logo.

**Top-right:** Green checkmark icon.

The green checkmark is the **Save button**.

### Logo

- Use the existing approved MatchMe logo.
- Keep its original proportions.
- Make it compact and professionally aligned.
- Do not add a large page heading above the form.

### Green Checkmark — Save

Use a recognizable green checkmark icon inside an accessible clickable control.

Requirements:

- The icon must be clearly visible.
- The button must have an accessible label: "Save Preferences".
- The icon must save all modified preferences.
- Validate selections before saving.
- Show a subtle loading state while saving.
- Prevent duplicate save submissions.
- Show a brief success confirmation after successful persistence.
- If saving fails, keep the user's changes and display an actionable error.
- Do not show success before the backend confirms persistence.
- After successful saving, return the user to the Swipe page.
- Refresh job recommendations using the updated preferences.
- Preserve the user's current Swipe session where appropriate.

The Save icon must remain easily accessible on mobile.

**Remove the existing Save button at the bottom of the Preferences page completely.**

Do not create a second Save button.

## 7. Roles & Keywords

The first section must be:

**Roles & Keywords**

Use a searchable type-ahead autocomplete field with multi-selection.

The user must be able to:

- Tap the field to open suggestions.
- Start typing to search for relevant job roles and keywords.
- Select multiple options.
- View selected options as removable chips.
- Remove individual selections.
- Edit selections before saving.

### Maximum Selection Limit

Allow a maximum of **10 total selections across Roles & Keywords combined**.

For example:

6 Roles + 4 Keywords = 10 selections.

Do not allow more than 10 combined selections.

Display a subtle counter:

**6/10 selected**

When the limit is reached:

- Prevent additional selections.
- Keep existing selections unchanged.
- Show a clear message explaining the limit.
- Allow the user to remove a selection before adding another.

### Autocomplete

Reuse the existing MatchMe canonical job-role and skills/keyword taxonomies.

Examples of role suggestions:

- Sales Executive
- Account Manager
- Marketing Manager
- Software Engineer

Suggestions must come from the actual canonical taxonomy, not a hardcoded example-only list.

Support keyword search using the existing normalized keyword architecture.

Prevent duplicate selections, including case-insensitive duplicates.

Preserve the distinction between roles and keywords in the underlying data model even if they share one combined user-facing section.
