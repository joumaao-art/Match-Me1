# MATCHME — JOB SEEKER PERSONAL INFORMATION RESTRUCTURING
## Identity | Contact | Compensation | Gender

### OBJECTIVE

Restructure the existing **Personal** page under Job Seeker → Profile → Personal into four categories, in the exact order specified below.

Implement these changes on both mobile and desktop, preserving each platform's existing layout, navigation, styling, and responsive behavior.

Reuse the existing Supabase profile records, validation, authentication, and data services.

Do not rebuild the Profile system, reset saved information, or create duplicate profile records.

---

## 1. IDENTITY

Create the first category with the heading:

**Identity**

Display the following fields in this exact order:

### Title
- Dropdown selection.
- Options:
  - Dr.
  - Mr.
  - Mrs.
  - Ms.
- Single selection.
- Include a placeholder: "Select title".
- Save the selected title to the existing Job Seeker profile, extending the schema safely if required.

### Legal First Name
- Text input.
- Mandatory.
- Prepopulate with the user's previously saved legal first name.
- Support appropriate Unicode characters for English and Arabic names.
- Trim unnecessary leading and trailing spaces.

### Legal Last Name
- Text input.
- Mandatory.
- Prepopulate with the user's previously saved legal last name.
- Apply the same validation rules as Legal First Name.

### Birthday
- Display the existing saved date of birth.
- Mandatory, consistent with the existing onboarding rules.
- Use the established mobile scrolling day/month/year date picker.
- On desktop, preserve the existing desktop-appropriate date entry interface.
- Validate actual calendar dates.
- Do not allow future birth dates.
- Preserve the existing age calculation where used.

Do not add additional Identity fields.

## 2. CONTACT

Create the second category with the heading:

**Contact**

Display these fields in this exact order:

### Email
- Display the user's registered email address.
- Prepopulate from the existing authenticated account.
- If editable, use the existing secure email-change and verification process.
- Do not directly modify the Supabase authentication email through an ordinary profile update.
- Keep the email synchronized across the account.

### Mobile
- Use a searchable country-code dropdown beside the mobile number field.
- Include supported international calling codes.
- Prepopulate the previously saved country code and mobile number.
- Validate the number using country-specific formatting where supported.
- Preserve the existing phone verification requirements.
- Do not overwrite the number during unrelated profile edits.

### Address
- Display the user's existing saved address.
- Include searchable Country and City dropdowns.
- Filter City selections based on the selected Country.
- Preserve any existing street/address details supported by the current profile model.
- Prepopulate all available address information.
- Do not overwrite saved address details when the user opens the page.

All Contact fields remain subject to the existing mandatory profile requirements.

## 3. COMPENSATION

Create the third category with the heading:

**Compensation**

Add the following field:

### Current Compensation

This field is **optional**.

Allow the Job Seeker to enter their current compensation.

Recommended input structure:

**Currency**
- Searchable dropdown.
- Support relevant international currencies using standardized currency codes.
- Do not assume the user is paid in SAR.

**Amount**
- Numeric input.
- Accept positive monetary amounts.
- Support appropriate decimal precision.
- Display the selected currency clearly.

**Payment Frequency**
- Dropdown options:
  - Monthly.
  - Annually.

Store the amount, currency, and payment frequency together as one compensation record.

Requirements:
- The user may leave the entire category blank.
- Do not block profile completion when compensation is missing.
- Do not reduce the user's profile completion percentage because compensation is not provided.
- Do not make compensation mandatory during onboarding.
- Allow the user to edit or clear previously entered compensation.
- Persist compensation securely in Supabase.
- Do not expose current compensation to Companies, other Job Seekers, or public profiles by default.
- Do not automatically include compensation in the VIA Resume PDF.
- Do not automatically use compensation for job matching or salary filtering without an explicit product rule and user consent.

Do not confuse Current Compensation with Expected Compensation or the compensation offered by a Company in a vacancy.
