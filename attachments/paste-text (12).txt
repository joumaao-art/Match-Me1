# MATCHME — ONE-WAY MOBILE-TO-DESKTOP JOB SEEKER SYNCHRONIZATION
## Mobile Is the Product Reference | Desktop Must Match | Preserve Independent Layouts

**PRIORITY: HIGH — JOB SEEKER ONLY**

## 1. PRIMARY OBJECTIVE

Audit the current, working MatchMe Job Seeker mobile application and synchronize the desktop Job Seeker experience to match it completely.

The mobile application is the authoritative reference for all Job Seeker features, workflows, fields, navigation destinations, business rules, and functionality.

This is a **ONE-WAY synchronization: MOBILE → DESKTOP ONLY**.

The desktop must adopt the current mobile functionality.

The mobile application must NOT be changed to accommodate the desktop.

Do not merge the two feature sets or reintroduce older desktop functionality into mobile.

### Non-negotiable principles

1. Mobile defines which Job Seeker features exist.
2. Desktop must support every mobile Job Seeker feature.
3. Desktop-only Job Seeker features must be removed from the visible desktop experience unless they are essential security, legal, accessibility, or platform-specific controls.
4. Preserve the mobile interface exactly as it currently works.
5. Preserve the desktop's existing professional layout and responsive structure.
6. Do not copy the mobile visual design onto desktop.
7. Do not change Company or Super Admin experiences.
8. Do not delete existing database records when removing desktop-only interface features.
9. Do not rewrite working authentication, billing, or application logic.
10. Do not introduce generated data, mock functionality, or placeholder buttons.

**The mobile application is the functional product specification. The desktop application is its desktop-optimized presentation.**

# PART 1 — AUDIT THE CURRENT MOBILE APPLICATION

## 2. Inspect the Actual Running Mobile Job Seeker Experience

Before making changes, inspect the existing mobile implementation and its current routes, components, services, and backend integrations.

Do not rely exclusively on previous documentation or older prompts.

The current mobile implementation takes precedence over outdated desktop code and historical specifications.

Audit:

- Welcome and authentication.
- Signup and onboarding.
- Swipe.
- Dashboard.
- Profile.
- Personal Information.
- Preferences.
- Experience.
- Education.
- Certifications.

Identify exactly what is currently implemented on mobile.

Distinguish functional features from unfinished or placeholder UI.

Do not copy known mobile bugs into desktop.

If a mobile feature is visibly present but nonfunctional, report the defect rather than treating it as successfully implemented.

## 3. Create a Mobile-to-Desktop Feature Matrix

For every Job Seeker feature, document:

- Mobile feature name.
- Mobile route or component.
- Mobile fields and options.
- Mobile actions.
- Mobile validation rules.
- Mobile backend service.
- Existing desktop equivalent.
- Desktop discrepancy.
- Required desktop change.
- Verification result.

Classify each desktop feature as:

**MATCH** — Already equivalent to mobile.

**ADD** — Exists on mobile but missing on desktop.

**UPDATE** — Exists on both but desktop is outdated.

**REMOVE FROM UI** — Exists only on desktop and is not part of the current mobile experience.

**EXCEPTION** — Required platform-specific, security, legal, or accessibility functionality.

Do not start broad refactoring before identifying these differences.

# PART 12 — REMOVE DESKTOP-ONLY FUNCTIONALITY

## 20. Desktop Feature Cleanup

After the full mobile-to-desktop audit, remove desktop-only Job Seeker interface elements that are absent from mobile.

This includes:

- Outdated navigation.
- Duplicate account sections.
- Legacy Profile fields.
- Obsolete preferences.
- Old application widgets.
- Redundant controls.
- Superseded screens.
- Unused desktop-only Job Seeker actions.

### Important safety distinction

Remove obsolete functionality from the **desktop interface**, not automatically from the database or shared backend.

Before removing anything:

1. Verify it truly has no current mobile equivalent.
2. Confirm it is not required by another mobile workflow.
3. Check whether it is needed for authentication, accessibility, legal compliance, billing, or account security.
4. Check whether other roles depend on the component or service.
5. Preserve existing user records.
6. Remove only the obsolete desktop presentation or entry point.
7. Update or redirect obsolete routes safely.

Do not delete production data.

Do not remove essential account controls merely because they are accessed differently on mobile.

Do not remove a desktop feature that is required to complete a mobile-equivalent workflow.
