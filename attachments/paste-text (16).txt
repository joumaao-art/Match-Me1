# PART 2 — ICON COLOR AND CONTRAST

## 3. Fix Invisible or Low-Contrast Icons

Inspect every icon's appearance in these states:

1. Default.
2. Hover.
3. Keyboard focus.
4. Pressed / Active.
5. Selected.
6. Disabled.

For every state, verify that the icon remains clearly distinguishable from its immediate background.

### Non-negotiable requirement

**Never use a white icon on a white or very light background.**

Likewise, never use a dark icon on a dark background without sufficient contrast.

The foreground and background must change together when necessary.

For normal-size icon graphics and meaningful control boundaries, target at least a 3:1 contrast ratio under WCAG non-text contrast guidance.

Where icons include essential text, apply the relevant text contrast requirements.

Do not fix visibility by adding unnecessary borders or changing the overall button layout.

# PART 3 — SWIPE ACTION BUTTONS

## 4. Fix the Pass (X) Button

The Swipe page contains three main actions:

- Pass (X).
- Save (Bookmark).
- Apply (Heart).

### Pass (X)

The current problem is that the X becomes white and difficult to see on hover.

Correct the styling so the X remains clearly visible in every interactive state.

Recommended treatment:

**Default**
- Red X icon.
- Light background.
- Subtle red border.

**Hover**
- Stronger red icon with a very light red background, OR
- White icon with a solid red background.

**Pressed**
- Clear visual feedback.
- Maintain sufficient contrast.

**Disabled**
- Use a distinguishable disabled appearance.
- Do not make the icon completely invisible.

Choose whichever treatment fits the existing MatchMe design system.

### Save (Bookmark)

Ensure:

- Bookmark remains visible on hover.
- Saved and unsaved states are distinguishable.
- Hover colors do not make the icon disappear.
- Tooltip displays "Save Job" or "Remove Saved Job", depending on the current state.

### Apply (Heart)

Ensure:

- Heart remains visible on hover.
- Blue background and white icon maintain sufficient contrast.
- Pressed and disabled states remain understandable.
- Tooltip displays "Apply for Job" where applicable.

Preserve the existing Pass, Save, and Apply functionality.

Do not change swipe gestures, credit deductions, or application behavior.

# PART 4 — ICON TOOLTIPS

## 5. Add Hover Tooltips

Introduce a reusable tooltip component for interactive icon-only controls.

When a user hovers over an icon with a mouse or trackpad, display a small tooltip identifying its purpose.

### Examples

| Icon | Tooltip |
|---|---|
| X | Pass Job |
| Bookmark | Save Job |
| Heart | Apply for Job |
| Back Arrow | Go Back |
| Share | Share Job |
| Preferences | Preferences |
| Credits | Available Credits |
| Search | Search |
| Information | Support & Settings |
| Edit | Edit |
| Trash | Delete |
| Download | Download |
| Upload | Upload CV |
| Moon | Dark Mode |
| Sun | Light Mode |
| Logout | Logout |

Use context-sensitive labels when the action changes.

For example:

- Save Job → Remove Saved Job.
- Expand Details → Collapse Details.
- Enable Notifications → Disable Notifications.

Avoid generic tooltips such as "Click Here", "Button", or "Action".

### Tooltip Design

Tooltips must:

- Use the existing MatchMe design system.
- Have readable text.
- Maintain sufficient foreground/background contrast.
- Appear close to the relevant icon.
- Avoid covering important page content.
- Not block clicks or taps.
- Automatically close when hover or focus ends.
- Work correctly in Light and Dark Mode.
- Respect the selected application language.

Use a short, consistent hover delay where appropriate.

# PART 5 — MOBILE TOUCH BEHAVIOR

## 6. Do Not Depend on Hover for Mobile Phones

Mobile phones generally do not have a hover interaction.

Therefore, implement adaptive behavior based on input capability.

### Mouse / Trackpad

- Display the tooltip on hover.
- Display it on keyboard focus.
- Hide it when the user leaves the icon or focus moves away.

### Touchscreen

- The first tap must perform the icon's intended action.
- Do not require users to tap twice because a tooltip appeared.
- Do not introduce tooltips that interfere with swipe gestures.
- Do not make long-press mandatory for discovering essential actions.

Where appropriate, allow a short explanatory label on long-press only if it does not conflict with the existing gesture system.

For critical actions, ensure the interface remains understandable without relying on tooltips.

Use accessible names for screen readers.

# PART 6 — ACCESSIBILITY

## 7. Make Icon Buttons Accessible

Every interactive icon-only button must have an accessible name describing its action.

Requirements:

- Use appropriate aria-label or equivalent native accessibility properties.
- Support keyboard focus where applicable.
- Show a visible focus indicator.
- Ensure tooltips do not replace accessible labels.
- Prevent tooltip text from being announced redundantly.
- Ensure disabled actions have understandable states.
- Preserve logical tab order.
- Maintain sufficient touch-target sizes.

For mobile touch controls, aim for comfortable touch targets without changing existing visible icon dimensions unnecessarily.

Do not make decorative icons focusable or interactive.
