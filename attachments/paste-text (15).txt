# MATCHME — MOVE DARK MODE CONTROL TO SETTINGS
## Mobile & Desktop | Job Seeker | Shared Theme Preference

### OBJECTIVE

Move the existing Dark Mode functionality into the **Settings** page for both the mobile and desktop Job Seeker applications.

The Dark Mode control should no longer appear as a standalone icon in the desktop sidebar or other primary navigation areas.

**Important:** Reuse the existing theme system. Do not rebuild the application's styling or redesign either platform.

---

## 1. DARK MODE CONTROL IN SETTINGS

Inside the existing Settings page, add a section called:

**Appearance**

Under Appearance, display:

**Theme**

Provide the following three options:

- Light Mode — Sun icon.
- Dark Mode — Moon icon.
- System Default — Device/system appearance icon.

Use a professional segmented control, radio selection, or compact settings row consistent with the existing design.

The user must be able to switch themes directly from Settings.

### Expected behavior

**Light Mode**
- Applies the existing light theme.

**Dark Mode**
- Applies the existing dark theme.

**System Default**
- Automatically follows the operating system's light/dark appearance preference where supported.

The selected option must be visually clear.

## 4. SYNCHRONIZE THEME PREFERENCE

Both mobile and desktop must use the same canonical theme preference for the authenticated Job Seeker.

If the user selects Dark Mode on mobile, the desktop must use Dark Mode when the account preference is next loaded or synchronized.

Likewise, changes on desktop must be reflected on mobile.

### Persistence

- Reuse the existing theme preference service if available.
- Persist the selected preference to the authenticated user's existing settings record in Supabase, extending the schema safely only if necessary.
- Cache the preference locally for fast initial rendering.
- Restore the preference after refresh and login.
- Use the server preference as authoritative when reconciling cross-device changes.
- Avoid visible light-to-dark flashing during page loading.
- Use System Default for new accounts when no explicit theme preference exists.
- Preserve existing users' saved theme choices during migration.

Do not create separate mobile and desktop theme preferences.

For logged-out users, retain the existing local or system-based theme behavior without exposing authenticated settings.
